# The shared UI libraries

The site and the games share how they look and much of how they behave
through the libraries under `frontend/lib/`. This skill says which piece to
reach for, how an app takes them up, and what a change to a library keeps. A
library's own `AGENTS.md` adds the few rules that are its own.

| Library          | For                                                                                                                                                                                                       | Its rules                           |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| `@fz/style`      | Every app, Angular or not: the palettes and tokens, the global stylesheet, fragments such as `.fz-button`, Sass mixins, `theme.js`, the fuzzball and the page's icons, and the stylelint preset           | `frontend/lib/style/AGENTS.md`      |
| `@fz/ui`         | Every Angular app: dialogs, the confirmation, the announcer, the theme's service and pickers, icons, the radio group, storage, the fuzzball and the wordmark                                              | `frontend/lib/ui/AGENTS.md`         |
| `@fz/game-ui`    | Angular games only: the game bar and its menus, Pause and Sound, the viewport and breakpoints, the page frame, the settings drawer, How to play, the stopwatch, the run's lifecycle and the debug menu    | `frontend/lib/game-ui/AGENTS.md`    |
| `@fz/core`       | A game's code with no framework, its rules above all: the seeded random, readers for stored JSON, a clock of fixed steps, an event log, a field's play, a run's stages and keys, sweeps and the sound mix | `frontend/lib/core/AGENTS.md`       |
| `@fz/brick-wall` | The wall games' code, laid out in a game's own layers: each entry is taken by the same layer of a game, or one above it                                                                                   | `frontend/lib/brick-wall/AGENTS.md` |
| `@fz/phaser`     | Games drawn with Phaser: the canvas component, the host, a scene's helpers, shapes, inks and bricks, and headless Phaser for specs. The `phaser-core` skill covers it                                     | `frontend/lib/phaser/AGENTS.md`     |
| `@fz/dev`        | Every workspace's checks and builds, never an app's bundle: the ESLint, TypeScript, Vitest and Vite presets, and what `tools/` scripts share                                                              | `frontend/lib/dev/AGENTS.md`        |

An entry maps into its library's `src/`, as the `exports` of its
`package.json` say: `@fz/ui/dialog` is `frontend/lib/ui/src/dialog/`, and
`@fz/core/clock` is `frontend/lib/core/src/clock.ts`.

## Reach for the library first

Before writing a style or a component, look for it here. An app writes its
own only for what is its alone. A row names the piece and its entry. The
piece's doc comment says what it takes and what it does.

### Tokens, classes and mixins: `@fz/style`

`fz.` below is `@use "@fz/style" as fz;`. A game's component stylesheets
take the same mixins, and `@fz/game-ui`'s, through the game's own toolkit
(a `@use` of the game's `styles` as `*`, which forwards `@fz/game-ui/toolkit`), so there
they carry no prefix. Each mixin's doc comment, in
`frontend/lib/style/src/toolkit/`, says the markup it styles.

| You need                                              | Use                                                                                                                                                                                                                                                                                                 |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A color                                               | A palette role, `var(--fz-<role>)`, one of `PALETTE_ROLES` in `frontend/lib/style/src/themes.ts`, or a tint of the text: `--fz-wash-1` to `-4` for a fill, `--fz-edge-1` to `-4` for a border; `--fz-accent-wash` and `--fz-danger-wash` for a chosen or a danger fill, and `--fz-focus-ring-color` |
| A label on a filled color                             | Its pair: `--fz-on-accent`, `--fz-on-warning`, `--fz-on-danger`, and `--fz-on-felt` for what is drawn on a game's table                                                                                                                                                                             |
| A bar, drawer, modal, card or well over a game        | A surface: `--fz-bar-glass`, `--fz-panel-glass`, `--fz-float`, `--fz-well`. Each is glass in a dark palette and solid in a light one                                                                                                                                                                |
| Space, type, radius, shadow, motion                   | The scales: `--fz-space-*`, `--fz-font-*`, `--fz-leading-*`, `--fz-radius-*`, `--fz-shadow-*`, `--fz-ease-*`, `--fz-duration-*`, `--fz-tap-target`                                                                                                                                                  |
| A button                                              | `class="fz-button"`, with a tone (`fz-button-secondary`, `-warning`, `-danger`) or a shape (`fz-button-circle`, `-block`, `-large`) beside it. | A small label                                         | `class="fz-badge"`, or `fz-badge fz-badge-accent`                                                                                                                                                                                                                                                   |
| Text only a screen reader reads                       | `class="fz-visually-hidden"`, or the `fz.visually-hidden` mixin                                                                                                                                                                                                                                     |
| A frosted surface, an icon button, a tap target       | `fz.glass($blur)`, `fz.icon-button`, `fz.tap-target`, `fz.transition(…)`, `fz.flex-center`                                                                                                                                                                                                          |
| A dialog's card, its close button, its tiles          | `fz.dialog-card($width)`, `fz.close-button` (`fz.corner-close-button` in the card's corner), `fz.field-label` over a setting, `fz.choice-tile`, `fz.start-tile` for a level a run starts at, `fz.result-card`                                                                                       |

| A panel beside a game's board, as a wide room's       | `fz.board-panel` on the panel, which the board lays where `@fz/phaser/layout`'s `sidePanels()` puts it                                                                                                                                                                                              |
| The fuzzball with no Angular                          | `FUZZBALL`, its shapes, `fuzzballShape()`, posed as plain geometry, and `fuzzballSvg()`, a file of it at any face, from `@fz/style/fuzzball`                                                                                                                                                        |
| The tab's icon                                        | Nothing of the page's own: `fuzzleyStyle()` writes the icons and the tags that link them (step 2 below), and `ThemeService` recolors the SVG to the palette in use                                                                                                                                  |

### A game's rules and view: `@fz/core`

| You need                                                  | Use                                                                                                                                                                                                                                                                                            |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A seeded random, a new seed, a shuffle                    | `createRandom(seed)`, `randomSeed()` and `shuffled()` from `@fz/core/random`; `drawAt(seed, n)` for the nth draw with none before it                                                                                                                                                           |

### A wall game's layers: `@fz/brick-wall`

An entry names its layer, `@fz/brick-wall/<layer>/<entry>`, and is
`frontend/lib/brick-wall/src/<layer>/<entry>.ts`. A wall game passes
`layered: ["@fz/brick-wall"]` to `phaserGameLayers()`, which lets each of
its layers take the library's entries of the same layer and those below
it, as its own fences allow, and its files held as the rules are the
library's `testing` entries.

## Palettes and their modes

- **The palette in use is `data-theme` on `<html>`,** which `theme.js` sets
  before anything paints and `ThemeService` changes. Each palette sets every
  role, and its `color-scheme`, in
  `frontend/lib/style/src/tokens/_palettes.scss`, and
  `frontend/lib/style/src/themes.ts` lists the palettes with their modes.
- **A tint of `--fz-text` turns with the mode:** dark in a light palette,
  light in a dark one. What lies on a game's table rather than on its chrome
  takes `--fz-on-felt`, the felt's own ink, instead.
- **An element can carry a palette of its own** (`data-theme` on it, as a
  swatch does). The tints and surfaces follow it there too.

## Adopting the libraries in an app

A new game starts as a copy of one, as `frontend/games/AGENTS.md` says, with
these steps done. The site and the Solitaire Collection are the worked
examples, and Minesweeper (`frontend/games/minesweeper/`) shows the steps
with nothing else around them.

1. **Depend on them.** List `"@fz/style": "workspace:*"` in the app's
   `package.json`, and for an Angular app `@fz/ui` and, for a game,
   `@fz/game-ui`, with their peers `@angular/aria` and `@angular/cdk`. Run
   `yarn install` from `frontend/`. Nothing in `lib/` is built: the app
   compiles each library from its source.
2. **Add the Vite plugin,** `fuzzleyStyle()` from `@fz/style/vite`, as
   `frontend/site/vite.config.ts` does. A game gets it from `@fz/dev/vite`'s
   `gameConfig()`. It writes `theme.js` and the page's icons, and the tags
   that load them at the top of `<head>`, so the page writes none of them.
   The page keeps its own `theme-color`.
3. **Load the global stylesheet first.** `@use "@fz/style/global";` at the
   top of the app's own, as in
   `frontend/games/solitaire/src/ui/app/styles/global.scss`, or
   `@use "@fz/style/tokens";` alone for a page that keeps its own reset and
   element styles. A game on `@fz/game-ui` uses `@fz/game-ui/global`
   instead, which loads it and publishes the bar's size as
   `--fz-bar-height` and `--fz-rail-width`. Every library rule sits in a
   cascade layer and the app's rules in none, so the app's always win:
   adjust a shared style by writing your own, never by out-specifying the
   library's.
4. **Lint with the preset.** `extends: ["@fz/style/stylelint"]`, as in
   `frontend/games/solitaire/stylelint.config.js`, listing in its
   `overrides` only a file that must write a color, such as a drawing's.
5. **Wire the Angular pieces.** Put one `<fz-announcer />` and one
   `<fz-confirm-dialog />` in the root template. Provide `THEME_COLOR_ROLE`
   where the browser's toolbar should take another role than `bar`, or
   `null` where the app sets `theme-color` itself, as
   `frontend/games/solitaire/src/ui/app/main.ts` does. Have the specs' setup
   call `installDialogPolyfill` from `@fz/ui/testing` and give each test
   `provideMemoryStorage()`, as `frontend/games/solitaire/test/test-setup.ts`
   does.
6. **Check text on the table.** Text on glass over the app's own table
   depends on the table too: hold it to 4.5:1 over every table color, as
   `frontend/games/solitaire/test/ui/app/styles/contrast.spec.ts` does. A
   game that draws on the palette's own roles checks what it draws in every
   palette instead, as
   `frontend/games/minesweeper/src/app/board/contrast.spec.ts` does. Each
   compiles the app's global stylesheet and measures it with
   `@fz/style/testing`.

## Changing a library

- **A piece added, renamed or given other inputs changes its row above in
  the same change.** No `AGENTS.md` lists what a library holds.
- **Everything shared carries `fz`:** tokens, classes, layers, selectors.
  An app's own names carry none.
- **A component reads no viewport.** What changes with the layout is an
  input the app binds, such as the bar's `compact`, to what a game's
  `GameViewportService` says or the site's own breakpoints.
- **A thing belongs in a library only when the apps mean the same by it.**
  Otherwise it stays in the app, until a second one needs it.
- **A palette role goes into every palette at once,** and into
  `PALETTE_ROLES` in `frontend/lib/style/src/themes.ts`. The build fails
  without the first and a spec without the second. Nothing fails a role
  that carries text, or sits behind it, with no pair in
  `frontend/lib/style/src/tokens/contrast.spec.ts`, so add it.
- **Accessibility is the component's job,** by the `web-game-accessibility`
  skill's rules, so an app can't forget them.
- **No library is built.** Every app compiles it from its source, so
  `yarn verify:changed` checks each app that depends on the one changed.
